# Аналитика: Яндекс.Метрика и статистика в админке

Инструкция для владельца магазина. После неё вы будете видеть:

- **сколько людей заходит на сайт** — на дашборде админки и на странице
  `/admin/analytics`;
- **сколько из них заказало** — график «Посетители и заказы» и конверсию в
  процентах;
- **откуда приходят покупатели** (поиск, ссылки, прямые заходы), **с чего
  смотрят** (телефон/компьютер), **из каких городов** и **на какие страницы
  заходят первыми**;
- **что люди делают на сайте** — цели: положил в корзину, применил промокод,
  начал оформление, оплатил, написал в поддержку.

Всё бесплатно: и сама Метрика, и её API.

## Часть 1. Счётчик на сайте (15 минут)

Без этого шага статистики не будет вообще.

### Шаг 1. Создать счётчик

1. Откройте [metrika.yandex.ru](https://metrika.yandex.ru) и войдите под тем
   Яндекс-аккаунтом, который будет владеть статистикой (лучше рабочим, не
   личным — доступ потом можно выдать сотрудникам).
2. Нажмите **Добавить счётчик**.
3. Заполните:
   - **Имя счётчика** — например, `Tomat Semena`;
   - **Адрес сайта** — `tomatsemena.ru`;
   - **Часовой пояс** — ваш (по нему Метрика режет сутки);
   - **Вебвизор, карта скроллинга, аналитика форм** — **включите**. Вебвизор
     записывает сеансы: видно, на каком поле человек бросил оформление заказа.
4. Примите условия и нажмите **Создать счётчик**.
5. На открывшейся странице найдите **номер счётчика** — 8–9 цифр (у новых
   счётчиков номер длиннее), например `123456789`. Он понадобится дальше.

> По пути Метрика попросит заполнить профиль. Для этого магазина: **тип сайта**
> — «Интернет-магазин», **индустрия** — «Дом и сад», **CMS** — «Другое» →
> «HTML код» (сайт собственной разработки, счётчик стоит обычным кодом),
> **CRM** — «Не использую» (заказы лежат в своей базе и видны в `/admin/orders`).
> Эти ответы ни на что не влияют — Метрика по ним только подбирает подсказки в
> интерфейсе, анкету можно и пропустить.

> Код счётчика с сайта Метрики копировать **не нужно** — он уже встроен в
> магазин (`components/analytics.tsx`). Нужен только номер.

### Шаг 2. Вписать номер в настройки сайта

На сервере откройте файл `.env.production` (рядом с проектом; локально —
`.env.local`) и впишите номер:

```
NEXT_PUBLIC_YANDEX_METRIKA_ID=98765432
```

Пересоберите и перезапустите сайт:

```bash
npm run build
pm2 restart tomatsemena     # или как у вас называется процесс
```

> **Почему обязательно пересобирать:** номер счётчика подставляется в страницы
> во время сборки. Без `npm run build` в HTML останется старое значение.

### Шаг 3. Проверить, что счётчик заработал

1. Откройте сайт в браузере (лучше в режиме инкогнито).
2. В Метрике зайдите в **Отчёты → Посещаемость** — визит появится в течение
   пары минут. Быстрее всего проверить в отчёте **Посетители → В реальном
   времени**.
3. Если визитов нет: на странице сайта нажмите `Ctrl+U` (исходный код) и
   поищите `mc.yandex.ru`. Нет ни одного совпадения — переменная не попала в
   сборку (не тот файл `.env`, забыли `npm run build`).

### Шаг 4. Создать цели

Сайт уже отправляет события в Метрику, но пока по ним нет **целей**, отчётов
тоже нет. Заведите их один раз:

1. Метрика → **Цели** (пункт левого меню; в старом интерфейсе — «Настройка →
   Цели») → **Добавить цель**.
2. Название — любое понятное (например, «Оформленный заказ»).
3. Тип условия — **JavaScript-событие**.
4. В поле **Идентификатор цели** впишите строку из таблицы ниже **точно как
   написано**, без пробелов.
5. Сохраните. Повторите для остальных целей.

| Идентификатор | Что означает | Нужна обязательно |
|---|---|---|
| `purchase` | Заказ оформлен (приходит с суммой заказа в ₽) | **да** |
| `begin_checkout` | Открыта страница оформления | **да** |
| `add_to_cart` | Товар добавлен в корзину | **да** |
| `submit_order` | Нажата кнопка «Оформить заказ» | желательно |
| `payment_failed` | Оплата не прошла | желательно |
| `remove_from_cart` | Товар удалён из корзины | по желанию |
| `add_to_favorites` | Товар добавлен в избранное | по желанию |
| `search` | Поиск по каталогу | по желанию |
| `promo_applied` | Применён промокод | по желанию |
| `signup` | Регистрация подтверждена | по желанию |
| `login` | Вход в аккаунт | по желанию |
| `support_request` | Отправлена заявка в поддержку | по желанию |
| `review_submit` | Отправлен отзыв о магазине | по желанию |

Пока цель не заведена, админка сама напомнит о ней: на `/admin/analytics` в
блоке «Цели, которых ещё нет в Метрике» перечислены только недостающие. Когда
цели появятся, на их месте встанет **воронка «Путь покупателя»** с цифрами.

Четыре главные цели дают воронку: `add_to_cart` → `begin_checkout` →
`submit_order` → `purchase`. По ней видно, на каком шаге теряются покупатели.

### Шаг 5. Включить электронную коммерцию

Магазин передаёт в Метрику состав заказов (какие сорта смотрели, клали в
корзину и купили). Чтобы отчёт заработал:

1. Метрика → **Настройки** (пункт левого меню, в самом низу) → вкладка
   **Счётчик**.
2. Пролистайте до раздела **«Электронная коммерция»**. Не видно — разверните
   **«Дополнительные настройки»** внизу вкладки, он прячется там.
3. Включите переключатель.
4. Поле **«Контейнер данных»** оставьте со значением `dataLayer`. Это не
   косметика: сайт кладёт данные именно в этот контейнер (задано при
   инициализации счётчика в `components/analytics.tsx`). Впишете другое имя —
   состав заказов до Метрики не дойдёт.
5. **Сохранить** внизу страницы.

Проверить, что сайт свою часть делает, можно сразу: откройте магазин, положите
товар в корзину, нажмите F12 → вкладка **Console**, наберите `dataLayer` и
Enter. В массиве должен появиться объект вида
`{ecommerce: {currencyCode: "RUB", add: {products: […]}}}`.

Сам отчёт — **Отчёты → Электронная коммерция → Заказы**: товары, выручка и «Топ
продаж» глазами Метрики. Данные появятся через несколько часов (нормально —
на следующий день) и только по заказам, сделанным ПОСЛЕ включения.

## Часть 2. Статистика посещаемости в своей админке (10 минут)

Счётчик собирает данные, но чтобы показать их **в админке магазина**, нужен
ключ доступа к API Метрики — OAuth-токен. Это отдельный секрет, он живёт
только на сервере.

### Шаг 1. Создать приложение в Яндекс OAuth

1. Откройте [oauth.yandex.ru](https://oauth.yandex.ru) под тем же аккаунтом,
   что владеет счётчиком, и нажмите **Создать приложение**.
2. **Название** — например, `Статистика для админки Tomat Semena`.
3. **Платформы** — отметьте **Веб-сервисы**. В поле *Redirect URI* нажмите
   ссылку **Подставить URL для отладки** (получится
   `https://oauth.yandex.ru/verification_code`).
4. **Доступы (Data access)** — найдите **Яндекс.Метрика** и отметьте
   **Получение статистики, чтение параметров** (`metrika:read`). Больше прав
   не нужно: токен сможет только читать.
5. Создайте приложение и скопируйте **ClientID**.

### Шаг 2. Получить токен

1. Откройте в браузере (подставив свой ClientID):

   ```
   https://oauth.yandex.ru/authorize?response_type=token&client_id=ВАШ_CLIENT_ID
   ```

2. Подтвердите доступ. Яндекс покажет строку вида
   `y0_AgAAAABZ...` — это и есть токен.
3. Скопируйте его целиком.

> Токен — как пароль от статистики. Не выкладывайте его в переписку, в git и в
> публичные файлы. Если утёк — отзовите на странице
> [oauth.yandex.ru/client/my](https://oauth.yandex.ru/client/my) и получите
> новый. Токен действует год; когда истечёт, админка честно напишет, что
> Метрика не приняла ключ — просто повторите этот шаг.

### Шаг 3. Вписать токен на сервере

В `.env.production` добавьте:

```
YANDEX_METRIKA_TOKEN=y0_AgAAAABZ...
# Необязательно: номер счётчика для API. По умолчанию берётся тот же, что
# стоит на сайте (NEXT_PUBLIC_YANDEX_METRIKA_ID) — заполняйте, только если
# читать нужно статистику ДРУГОГО счётчика.
YANDEX_METRIKA_COUNTER_ID=
```

Пересоберите и перезапустите сайт:

```bash
npm run build
pm2 restart tomatsemena
```

### Шаг 4. Проверить

Откройте `/admin/analytics`. Должны появиться:

- плитки **Визиты / Посетители / Заказы / Конверсия / Выручка** с изменением к
  прошлому периоду;
- график **«Посетители и заказы»** — две панели с общей осью дней;
- срезы: источники, устройства, города, страницы входа;
- переключатель периода: 7 / 14 / 28 / 90 дней.

На дашборде (`/admin`) появится плитка **«Посетителей за 7 дней»** с
мини-графиком, числом заказов и конверсией.

Если вместо цифр висит сообщение об ошибке:

| Сообщение | Что делать |
|---|---|
| «Статистика Метрики не подключена» | Нет `YANDEX_METRIKA_TOKEN` или номера счётчика; проверьте `.env.production` и что сайт пересобран |
| «Метрика не приняла токен» | Токен истёк, отозван или у аккаунта нет доступа к счётчику — получите новый (часть 2, шаги 1–2) |
| «Метрика не отвечает» | Временный сбой или нет интернета на сервере; данные подтянутся при следующем обновлении |

## Часть 3. Что делать с конверсией

**Конверсия — это доля визитов, которые закончились заказом.** 2% значит: из
каждых 100 заходов на сайт заказ оформляют двое. Считается по вашей базе
заказов и визитам из Метрики, поэтому получается чуть выше «метрикиной»
(Метрика недосчитывает визиты из-за блокировщиков).

Ориентиры для розничного интернет-магазина:

| Конверсия | Как читать |
|---|---|
| 2% и выше | отличный результат |
| 0,8–2% | нормально, так живёт большинство магазинов |
| ниже 0,8% | стоит посмотреть, где теряются люди |
| 0% при сотнях визитов | скорее всего что-то сломано: проверьте оформление заказа руками |

**Гнаться за абсолютной цифрой не нужно.** Смысл в том, куда она движется:

- растёт при том же трафике — сайт стал понятнее;
- падает сразу после запуска рекламы — привели не тех людей (это нормально,
  смотрите не конверсию, а число заказов);
- скачет от недели к неделе у сезонного товара — так и должно быть.

**Где искать причину.** Для этого и нужна воронка «Путь покупателя» на
`/admin/analytics`: она показывает, сколько визитов дошло до каждого шага и на
каком переходе теряется больше всего людей относительно обычного. Админка сама
подписывает узкое место и что обычно с ним делают. Типичные случаи:

| Проваливается переход | Что обычно виновато |
|---|---|
| зашли → положили в корзину | карточка товара: мало фото, нет описания сорта, нет в наличии, цена |
| корзина → оформление | доставка: её стоимость видна слишком поздно, не заметен порог бесплатной |
| оформление → кнопка «Оформить» | форма: много полей, капча, адрес ПВЗ |
| кнопка → заказ | техника: ошибки оплаты; смотрите цель `payment_failed` и заказы «Ожидает оплаты» |

Разбирать имеет смысл, когда за период набралось хотя бы пара десятков визитов
— на трёх визитах любые проценты случайны, и админка советов не даёт.

## Как это устроено (для разработчика)

| Файл | За что отвечает |
|---|---|
| `components/analytics.tsx` | Сам счётчик на сайте (Вебвизор, ecommerce), подключается только при заданном `NEXT_PUBLIC_YANDEX_METRIKA_ID` |
| `lib/metrika.ts` | Цели и слой данных электронной коммерции; здесь же список идентификаторов целей |
| `lib/metrika-stats.ts` | Чтение Stat API v1 (server-only), кэш 10 минут, разбор ответов |
| `lib/traffic-series.ts` | Сведение визитов и заказов в один ряд, конверсия, сравнение периодов |
| `lib/funnel.ts` | Шаги воронки, переходы между ними, поиск узкого места |
| `app/admin/analytics/page.tsx` | Страница аналитики |
| `components/admin/traffic-chart.tsx` | График «Посетители и заказы» |
| `components/admin/goal-funnel.tsx` | Воронка «Путь покупателя» и разбор конверсии |
| `components/admin/visitors-card.tsx` | Плитка посещаемости на дашборде |
| `tests/metrika.test.ts`, `tests/funnel.test.ts` | Тесты разбора ответов API, конверсии и воронки |

Полезное про поведение системы:

- **Без переменных ничего не ломается.** Нет номера счётчика — на сайте нет ни
  строчки кода Метрики (локальные визиты не пачкают статистику). Нет токена —
  админка работает, просто вместо посещаемости показывает инструкцию.
- **Аналитика не может уронить покупку**: все вызовы счётчика обёрнуты в
  `try/catch` (блокировщики рекламы вырезают `tag.js` — это нормально).
- **Цель `purchase` засчитывается на странице «спасибо»**, а не при отправке
  формы: при онлайн-оплате заказ ещё может сорваться на форме банка. Состав
  заказа переживает переход в `sessionStorage` и забирается ровно один раз —
  обновление страницы второй покупки в статистику не добавит.
- **Заказы в админке считаются по своей базе, а не по Метрике.** Метрика может
  не досчитать визиты (блокировщики, отключённый JS), но заказ — это запись в
  базе. Поэтому конверсия = заказы из базы ÷ визиты из Метрики, и она чуть
  выше «метрикиной».
- **Лимит API** — 5000 запросов в сутки на счётчик. Ответы кэшируются на 10
  минут, так что даже при постоянно открытой админке лимит недостижим.
- **Расхождение с интерфейсом Метрики в 1–2%** — норма: данные там
  досчитываются несколько часов.

## Переменные окружения — коротко

| Переменная | Где | Обязательна | Зачем |
|---|---|---|---|
| `NEXT_PUBLIC_YANDEX_METRIKA_ID` | браузер | для сбора статистики | Номер счётчика; включает Метрику на сайте |
| `YANDEX_METRIKA_TOKEN` | только сервер | для админки | OAuth-токен, читает статистику |
| `YANDEX_METRIKA_COUNTER_ID` | только сервер | нет | Другой счётчик для API |

> Google Analytics на сайте нет и поддержки его тоже: он передаёт данные
> посетителей за границу, а по 152-ФЗ персональные данные россиян должны
> обрабатываться на серверах в России. Это самое частое нарушение у небольших
> магазинов, и заводить его ради дублирования Метрики нет смысла.
