# 🔐 Регистрация: только российская почта + антибот (SmartCaptcha)

Что уже сделано в коде:
- **Регистрация только с российской почты** — домены `.ru` / `.рф` / `.su` и
  известные российские провайдеры (Яндекс, Mail.ru, Rambler, VK). Иностранные
  (gmail, outlook и т.п.) отклоняются. Проверка на сервере (`lib/ru-email.ts`),
  обойти из браузера нельзя.
- **Прямое создание аккаунтов в PocketBase закрыто** — регистрация идёт только
  через серверный роут `/api/register` (проверка почты + капчи, создание
  суперпользователем без права выдать себе роль admin).
- **Антибот-капча** (Yandex SmartCaptcha) на регистрации, форме поддержки и
  кнопке «Оплатить» — включается ключами; пока ключей нет, капча выключена и
  формы работают как есть.
- **Аккаунт заводится сам после успешной оплаты**, если покупатель оформлял
  заказ гостем и его почты ещё нет в базе: сайт придумывает надёжный пароль и
  присылает его письмом, ФИО и телефон переносит из заказа
  (`lib/auto-account.ts`). Условия те же, что у обычной регистрации: почта
  российская, SMTP настроен — иначе пароль было бы некуда отправить, и аккаунт
  просто не создаётся. Заказ, оформленный на уже зарегистрированную почту,
  после оплаты появляется в истории этого аккаунта.
- **Смена пароля в личном кабинете** (раздел «Безопасность»): текущий пароль
  проверяет сам PocketBase, поэтому с угнанной сессией пароль не сменить; после
  смены сессия перевыпускается, а другие устройства выходят
  (`/api/account/password`).
- **Сброс забытого пароля** — страница `/password-reset` (ссылка «Забыли
  пароль?» у поля пароля на входе): почта + капча → 6-значный код письмом →
  новый пароль. Сделано своим кодом, а НЕ встроенным сбросом PocketBase: тот
  шлёт письмо своим почтовиком (настройки у него отдельные и обычно пустые), а
  ссылка в письме ведёт в админку PocketBase — покупателю там делать нечего.
  Код живёт те же 5 минут (`EMAIL_CODE_TTL_MIN`), прежние коды после повторной
  отправки продолжают работать. Ответ на первом шаге одинаковый для
  существующей и несуществующей почты — по странице нельзя перебирать, у кого
  есть аккаунт. После смены владельцу уходит письмо «пароль изменён».
- **Вход через Яндекс ID и VK ID** — кнопки на `/login` и `/register`,
  появляются, когда провайдер настроен (см. раздел ниже). Пароль придумывать не
  нужно: почта и имя приходят от сервиса.
- **Вход и регистрация связаны переключателем** в шапке карточки, а не строкой
  под кнопкой. На регистрации есть плашка: заводить аккаунт заранее не
  обязательно — после первой оплаты он создастся сам.

Проверено вживую: иностранная почта отбивается, российская проходит, дубликат и
короткий пароль отклоняются, прямое создание аккаунта анонимом → 403.

## Применить на сервере

Ограничение по почте и серверная регистрация уже работают после обычного
обновления — нужно только подтянуть код и **переимпортировать схему** (в ней
закрыто прямое создание users):

```bash
cd /var/www/seeds/seeds
git pull
npm run db:schema        # применит закрытие createRule у users
bash deploy/update.sh
```

Проверка: на `/register` попробуйте `test@gmail.com` — должно отказать, а
`test@yandex.ru` — принять.

## Включить капчу (Yandex SmartCaptcha) — бесплатно

1. В [console.yandex.cloud](https://console.yandex.cloud) → сервис **SmartCaptcha**
   → **Создать капчу**. Тип — «Невидимая» или «Я не робот» (любой).
   В настройках домена укажите `tomatsemena.ru`.
2. После создания скопируйте **два ключа**:
   - **Клиентский ключ** (client key) — публичный, идёт в браузер;
   - **Серверный ключ** (server key) — секретный.
3. На сервере добавьте в `.env.production`:
   ```
   NEXT_PUBLIC_SMARTCAPTCHA_SITE_KEY=клиентский-ключ
   SMARTCAPTCHA_SERVER_KEY=серверный-ключ
   ```
4. Пересоберите (клиентский ключ вшивается при сборке):
   ```bash
   bash deploy/update.sh
   ```

Теперь на регистрации и в форме поддержки появится виджет «Я не робот», а сервер
проверяет токен капчи через `smartcaptcha.yandexcloud.net`. Без пройденной капчи
регистрация/заявка не отправляется.

> Если сервис капчи вдруг недоступен — сервер не блокирует пользователя
> (fail-open), чтобы из-за сбоя Яндекса не встал приём заявок. Ограничение по
> российской почте при этом продолжает работать всегда.

## Вход через Яндекс ID и VK ID — бесплатно

Кнопки «Войти через Яндекс ID» и «Войти через VK ID» появляются на `/login` и
`/register`, только когда соответствующий провайдер настроен. Можно включить
любой один, оба или ни одного: пока не настроен ни один — блока просто нет,
вход по паролю работает как работал.

Как это устроено: авторизацию берёт на себя PocketBase (у него встроенные
провайдеры `yandex` и `vk`), а сессию в httpOnly-cookie кладёт сайт — так же,
как при обычном входе. Ключи приложения живут ТОЛЬКО в PocketBase: сайту они не
нужны, и лишняя копия секрета никому не сдалась.

### Яндекс ID

1. Заведите приложение на [oauth.yandex.ru](https://oauth.yandex.ru/client/new):
   - платформа — **Веб-сервисы**;
   - **Redirect URI**: `https://tomatsemena.ru/api/auth/oauth/callback`
     (адрес должен совпадать до символа);
   - доступы (scopes) — нужны **все три**, PocketBase запрашивает именно их:
     - `login:email` — «Доступ к адресу электронной почты»,
     - `login:info` — «Доступ к логину, имени и фамилии, полу»,
     - `login:avatar` — «Доступ к портрету пользователя».

   > Если хотя бы одного доступа у приложения нет, Яндекс не пустит дальше и
   > покажет **`invalid_scope`** («This application does not have the requested
   > access permissions»). Аватар сайту не нужен, но запрос идёт «пакетом»:
   > лишний доступ в приложении дешевле, чем неработающая кнопка.
2. Скопируйте **ClientID** и **Client secret** и добавьте в `.env.production`:

   ```
   YANDEX_CLIENT_ID=идентификатор-приложения
   YANDEX_CLIENT_SECRET=пароль-приложения
   ```

### VK ID

1. Заведите приложение на [dev.vk.com](https://dev.vk.com/) → «Мои приложения»
   → «Создать приложение», тип — **Веб-сайт** (не Standalone: для входа с
   возвратом на сайт нужен именно он).

   > На шаге «Способы быстрого входа в web-приложении» (One Tap, шторка
   > авторизации, виджет «3 в 1») жмите **«Настроить позже»**. Это виджеты
   > VK ID SDK — они встраиваются в страницу и работают на JavaScript, а у нас
   > вход server-side: браузер уходит на страницу согласия обычной ссылкой, код
   > на сессию меняет PocketBase. SDK не подключается, эти галочки ни на что не
   > влияют. «Виджет 3 в 1» тоже не даёт входа через Одноклассники и Mail — он
   > работает только внутри самого виджета.
2. В настройках приложения:
   - **Адрес сайта**: `https://tomatsemena.ru`, **базовый домен**:
     `tomatsemena.ru`;
   - **Доверенный Redirect URI**:
     `https://tomatsemena.ru/api/auth/oauth/callback` — адрес должен совпадать
     до символа, иначе ВКонтакте откажет с ошибкой про `redirect_uri`;
   - доступ: **email** (это единственный доступ, который запрашивает
     PocketBase).
3. Скопируйте **ID приложения** и **Защищённый ключ** в `.env.production`:

   ```
   VK_CLIENT_ID=идентификатор-приложения
   VK_CLIENT_SECRET=защищённый-ключ
   ```

> **Важно про почту у ВКонтакте.** Аккаунт, заведённый только по номеру
> телефона, почты не отдаёт — а без неё покупателю некуда слать чек (54-ФЗ) и
> письма о заказе, поэтому аккаунт на сайте не создастся. Такой человек увидит
> честное объяснение и предложение зарегистрироваться по почте. У Яндекс ID
> почта есть всегда, там этой ситуации не бывает.

### Применить

```bash
cd /var/www/seeds/seeds
npm run db:schema     # пропишет провайдеров в PocketBase
bash deploy/update.sh
```

Скрипт схемы **не теряет** эту настройку при последующих запусках: перед
импортом он читает текущую конфигурацию OAuth2 и возвращает её обратно, а ключи
из `.env.production` при их наличии выигрывают. Настроить можно и вручную —
админка PocketBase → Collections → `users` → Options → OAuth2, но тогда держите
ключи и в `.env.production`, иначе следующий импорт схемы вернёт старое
состояние.

Что происходит при входе:

- аккаунта не было — PocketBase заводит его сам, почту и имя берёт у сервиса;
- аккаунт с такой почтой уже есть — вход в него, заказы и данные на месте;
- пароля у такого аккаунта нет. Если он понадобится (например, чтобы входить и
  по паролю), покупатель задаёт его через «Забыли пароль?» — код придёт на ту
  же почту.

Ограничение «только российская почта» на этот вход не распространяется: и
Яндекс, и ВКонтакте — российские сервисы, а лишняя проверка отправляла бы
человека в тупик уже после согласия на их странице.

### Если вход через Яндекс или ВКонтакте не работает

Точная причина всегда в `pm2 logs seeds`, строки `[oauth]`.

| Что видно | Что делать |
|-----------|-----------|
| `invalid_scope` / «This application does not have the requested access permissions» | Приложению не выданы нужные доступы. Яндекс — все три: `login:email`, `login:info`, `login:avatar`. ВКонтакте — `email` |
| Ошибка про `redirect_uri` | В приложении указан другой адрес возврата. Нужен ровно `https://tomatsemena.ru/api/auth/oauth/callback` — без слэша на конце, тот же домен и протокол. У ВКонтакте это поле называется «Доверенный Redirect URI» |
| «ВКонтакте не передал вашу почту» | У аккаунта ВК нет привязанной почты (заведён по телефону). Это не чинится настройками — покупателю остаётся регистрация по почте |
| Кнопки входа нет на странице | Провайдер не включён в PocketBase: проверьте `YANDEX_CLIENT_ID`/`YANDEX_CLIENT_SECRET` и `VK_CLIENT_ID`/`VK_CLIENT_SECRET` в `.env.production` и запустите `npm run db:schema` |
| «Вход через … сейчас недоступен» на сайте | То же, что выше, либо PocketBase не отвечает — `/api/health` и `pm2 logs seeds` |
| В логе `потеряна cookie рукопожатия` | Между уходом на сервис и возвратом истекли 10 минут, либо сайт открыт по другому домену, чем указан в `SITE_URL` |

## Как работает ограничение по почте

Разрешены: любой адрес в зонах **.ru / .рф / .su**, а также Яндекс (yandex.ru,
ya.ru, yandex.com), Mail.ru (mail.ru, list.ru, bk.ru, inbox.ru), Rambler, VK.
Список провайдеров — в `lib/ru-email.ts`, при необходимости дополняется.

Существующие аккаунты (если заводили) не затрагиваются — правило действует
только на новую регистрацию.
