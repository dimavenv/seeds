# Аккаунт после оплаты и одноразовый сброс пароля

Дата: 24 сентября 2026 года. Ветка публикации: `deploy/seeds-20260904`.

## Поведение

- Онлайн-заказ создаётся в статусе ожидания оплаты. На этом этапе гостю не
  создаётся аккаунт и не отправляется письмо доступа.
- После подтверждения платежа сервер ищет пользователя по email без учёта
  регистра. Если аккаунт существует, заказ связывается с ним; пароль и профиль
  не меняются, новое приветственное письмо не отправляется.
- Для нового email создаётся аккаунт покупателя. На почту отправляются логин
  (email) и одноразовая ссылка для самостоятельного задания пароля.
  Случайный внутренний пароль не отправляется и не попадает в ссылку.
- Обработчик дожидается создания аккаунта и попытки отправки письма.
- Существующее поведение оплаты при получении сохранено: кабинет создаётся
  после принятия такого заказа, поскольку онлайн-платежа у него нет.
- Восстановление доступа отправляет ссылку на форму нового пароля. Она действует
  30 минут по умолчанию (`PASSWORD_RESET_TTL_MIN`, допустимо 10–1440 минут).
- В базе хранится SHA-256 токена, коллекция закрыта для публичного доступа.
  Новый запрос отменяет предыдущую ссылку того же назначения.
- Погашение ссылки и смена пароля выполняются в одной Batch-транзакции.
  Одновременное использование одной ссылки успешно только один раз;
  откат транзакции сохраняет ссылку при ошибке смены пароля.
- Сохранены капча, ограничения частоты запросов и одинаковый ответ для
  существующих и неизвестных email. На странице пароля отключено подключение
  аналитики, установлен `no-referrer`.
- Ссылки сохранены и в текстовой версии письма, не только в HTML.

## Проверки

Проверена отдельная копия именно подготовленного коммита, без остальных
незакоммиченных изменений рабочей папки:

- 452 теста в 35 файлах прошли, включая запуск отдельного живого PocketBase.
- Проверены создание аккаунта после оплаты, повторный платёж, сохранение
  пароля существующего пользователя, содержание письма, отказ SMTP,
  повторное и конкурентное использование ссылки, срок действия и откат.
- ESLint и production-сборка Next.js с проверкой типов прошли.
- Настоящие платежи и письма покупателям при тестировании не отправлялись.

Дополнительные проверки репозитория не полностью зелёные: `audit:check`
сообщает о зависимостях browserslist, nodemailer и sharp; Next.js и вложенный
postcss отмечены существующим списком исключений. `scan:secrets` обнаруживает
исторический путь `.env.local` из коммитов июня 2026 года. Этот файл не добавлен
текущей задачей. Эти проблемы требуют отдельного исправления.

## Применение на VPS

Публикация в GitHub сама по себе не обновляет работающий VPS: в репозитории
настроены CI-проверки, но не автоматический SSH-деплой.

```bash
cd /var/www/seeds/seeds
git pull --ff-only
npm run db:schema
bash deploy/update.sh
```

Импорт должен создать `password_reset_tokens` и включить Batch API.
Проверить SMTP и правильный адрес сайта (`NEXT_PUBLIC_SITE_URL` / `SITE_URL`).
После обновления проверить своим адресом реальное получение письма, переход
по ссылке, вход и отказ при повторном использовании ссылки.

Если SMTP не принял приветственное письмо, аккаунт остаётся созданным;
покупатель может запросить новую ссылку через «Забыли пароль?». Автоматической
фоновой очереди повторной доставки после перезапуска процесса здесь нет.

Прежние изменения возвратов, административных действий и страниц заказа
оставлены в рабочей папке вне этого коммита.
