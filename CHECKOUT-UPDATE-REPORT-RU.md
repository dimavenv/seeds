# Изменения оформления заказа — 25 сентября 2026

## Что изменилось

1. После успешного сохранения заказа корзина очищается до перехода к оплате.
   На сервере очищаются товары из `user_store`, избранное сохраняется. Локальная
   корзина записывается синхронно; перед переходом завершается очередь её записи.
   Запоздавший первоначальный снимок сервера не должен возвращать удалённые товары.
   Заказ получает `cart_cleared`: подтверждение платежа не очищает новую корзину.
   Ошибка оформления не считается успешным заказом и не очищает локальную корзину.

2. Новые номера заказов случайные, от 10000 до 99999. Ведущих нулей нет.
   Уникальность обеспечивает индекс PocketBase, коллизии приводят к повторному
   выбору номера. Существующие номера не перенумеровываются. Номер счёта банка
   остаётся отдельным полем и не используется как номер заказа.

3. УРОЖАЙ разрешён только для первого созданного заказа на нормализованный email,
   включая гостевой. Проверяются и исторические зашифрованные адреса.
   Неоплаченный заказ тоже считается первым: его можно продолжить со скидкой
   по ссылке из письма. Уникальный `first_order_email_key` в заказах защищает
   от двух конкурентных первых заказов на один email. Старый заказ без промокода
   также исключает применение УРОЖАЙ в следующем заказе.
   Для вошедшего покупателя email в форме доступен только для чтения, а сервер
   берёт адрес из сессии независимо от присланного тела запроса.

4. Неоплаченный онлайн-заказ не создаёт аккаунт. При оформлении отправляется
   письмо «Ожидает оплаты» с кнопкой «Продолжить оформление». Подписанная ссылка
   действует 30 дней и открывает страницу с одной кнопкой продолжения оплаты.
   Вход и регистрация не требуются; при истечении резерва наличие проверяется
   повторно. Оплаченный/отменённый заказ повторно оплатить нельзя. Ссылка
   привязана к внутреннему ID заказа и не позволяет подменить его номером.
   Пароль для нового аккаунта по-прежнему отправляется только после оплаты.

## Проверки

В отдельной копии состава коммита прошли 475 тестов в 40 файлах,
ESLint и production-сборка с проверкой TypeScript.
Интеграционные тесты запускают отдельный PocketBase и проверяют шифрованные email,
гонку УРОЖАЙ, коллизию номера, корзину до/после оплаты и содержание письма.
Дополнительно проверяются подпись/истечение ссылки, отказ по поддельному токену,
привязка к нужному заказу и подмена email вошедшего пользователя.
Реальные платежи и письма покупателям во время проверок не отправляются.

## Применение на сервере

GitHub-публикация не обновляет VPS автоматически. Ветка: `deploy/seeds-20260904`.

```bash
cd /var/www/seeds/seeds
git pull --ff-only
npm run db:schema
bash deploy/update.sh
```

Импорт обязателен: добавляются `orders.cart_cleared`,
`orders.first_order_email_key` и уникальный индекс первого заказа.
После обновления проверить реальное письмо и переход к оплате на своей почте.

Прежние незакоммиченные изменения возвратов и административных действий
не входят в эту публикацию. Ранее выявленные проблемы аудита зависимостей
и исторического `.env.local` этой задачей не исправляются.
