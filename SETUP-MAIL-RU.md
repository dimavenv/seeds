# ✉️ Почта магазина: доступ к кабинету + письма о статусе заказа

Что уже сделано в коде (включается ключами SMTP, без них всё работает как раньше):

- **Доступ к кабинету после первого заказа**: сайт создаёт покупателю аккаунт и
  присылает пароль на почту из заказа. При онлайн-оплате это происходит после
  подтверждения платежа.
- **Письма о заказе** — приходят и гостям, и зарегистрированным (почта берётся
  из формы оформления заказа, аккаунт не нужен):
  - «Заказ принят» — сразу после оформления, с составом и суммой;
  - «Оплата получена» — после онлайн-оплаты (по уведомлению Robokassa);
  - «В обработке» / «Отправлен» (с трек-номером) / «Выполнен» / «Отменён» —
    при смене статуса в админке;
  - «Возврат оформлен» — при возврате денег (частичный — со списком позиций).
- **Уведомления продавцу** (см. раздел «Уведомления продавцу» ниже):
  «🛒 Новый заказ», «⭐ Новый отзыв», «💬 Вопрос в поддержке» — на служебный
  ящик, например `service@tomatsemena.ru`.

Это решает вопрос «гость оплатил и пропал»: покупатель без аккаунта получает
номер заказа и все изменения статуса на почту.

---

## Шаг 1. Почтовый ящик, с которого шлём

Код работает с любым SMTP — выбирай по бюджету:

**Вариант А — бесплатно, запуск за 10 минут: обычный ящик `@yandex.ru`.**
Например, `tomatsemena@yandex.ru`. Письма будут «от @yandex.ru», зато ноль
рублей, никаких DNS-записей и отличная доставляемость (домен Яндекса).
1. Заведи ящик на yandex.ru.
2. В настройках ящика: «Почтовые программы» → включить **IMAP/SMTP**.
3. [id.yandex.ru](https://id.yandex.ru) → Безопасность → **Пароли приложений** →
   создать для «Почты» — он пойдёт в `SMTP_PASSWORD` (обычный пароль не сработает).
4. SMTP: `smtp.yandex.ru`, порт `465`.

**Вариант Б — почта на своём домене (`info@tomatsemena.ru`), ~180 ₽/мес.**
Например, «Почта» у рег.ру (или у хостера домена):
1. Подключи услугу к домену, создай ящик `info@`.
2. Добавь DNS-записи из панели: **MX**, **SPF**, **DKIM** — без SPF/DKIM письма
   улетают в спам, это обязательная часть.
3. SMTP-хост/порт возьми из панели услуги (у рег.ру обычно
   `mail.hosting.reg.ru`, порт `465`).

**Вариант В — Яндекс 360 для бизнеса.** Тот же результат, что и Б, но у Яндекса
бесплатного тарифа для новых организаций больше нет (от ~600 ₽/мес за
сотрудника) — для одного ящика магазина смысла мало.

Начать можно с варианта А, а когда захочется писем «от домена» — перейти на Б:
в коде ничего менять не нужно, только значения SMTP_* в `.env.production`.

## Шаг 2. Ключи на сервере

В `.env.production` добавь:

```
SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
SMTP_USER=info@tomatsemena.ru
SMTP_PASSWORD=пароль-приложения
MAIL_FROM="Томат Семена <info@tomatsemena.ru>"
```

> `MAIL_FROM` должен совпадать с ящиком `SMTP_USER` (или его алиасом) — иначе
> провайдер отклонит отправку.

## Шаг 3. Проверить и включить

```bash
cd /var/www/seeds/seeds
node scripts/check-mail.mjs твоя@почта.ru   # тестовое письмо + подсказки при ошибке
bash deploy/update.sh                        # пересборка и перезапуск сайта
```

Проверка вживую: оформи и оплати тестовый заказ со своей почтой — придут письмо
об оплате и данные нового кабинета; смени статус в `/admin/orders` — придёт
письмо о статусе.

## Уведомления продавцу: новый заказ / отзыв / вопрос

Чтобы не проверять админку вручную, сайт умеет слать уведомления тебе на почту:

- **🛒 Новый заказ** — состав, сумма, способ оплаты, телефон/почта/адрес
  покупателя и кнопка «Открыть заказ в админке». Без онлайн-оплаты — сразу
  после оформления; с онлайн-оплатой — после успешной оплаты (неоплаченные
  заказы удаляются, пустой шум не приходит).
- **⭐ Новый отзыв** — оценка звёздами, текст и кнопка «Проверить и
  опубликовать» (модерация).
- **💬 Вопрос в поддержке** — тема и текст; кнопка «Ответить» в почтовике
  пишет сразу покупателю (Reply-To).
- **Ответ из админки**: в `/admin/support` под каждой заявкой есть форма —
  пишешь ответ, покупателю уходит письмо с цитатой его вопроса, заявка
  помечается «Отвечено», ответ сохраняется под заявкой. Покупателю письмо
  приходит с ОСНОВНОГО ящика (`info@`) — служебные адреса покупатели не видят;
  его ответ на письмо тоже придёт на основной ящик.
- Если отдельный ящик категории не сработал (неверный пароль и т.п.) —
  уведомление автоматически уходит с основного ящика, ничего не теряется
  (причина — в `pm2 logs seeds`, строки `[mail]`).

### Как включить (минимум)

1. Создай служебный ящик, куда всё будет падать — например,
   `service@tomatsemena.ru` (в панели почты домена, как в шаге 1Б).
   Его пароль сайту НЕ нужен: сайт на него только шлёт, а читаешь ты.
2. В `.env.production` добавь:

```
ADMIN_NOTIFY_EMAIL=service@tomatsemena.ru
```

Можно несколько получателей через запятую.

### Вторая, обычная почта (Яндекс, Gmail, Mail.ru)

Чтобы уведомления падали ещё и на личный ящик, который читаешь с телефона,
есть ОТДЕЛЬНАЯ переменная — `ADMIN_NOTIFY_EMAIL_EXTRA`:

```
ADMIN_NOTIFY_EMAIL=service@tomatsemena.ru
ADMIN_NOTIFY_EMAIL_EXTRA=твоя-почта@yandex.ru
```

Адреса из обеих переменных складываются, повторы отбрасываются; в каждой
можно перечислить несколько через запятую. Переменных две нарочно: личную
почту меняют чаще, и правка одной строки не рискует стереть служебный адрес.
Если строка не похожа на адрес, она пропускается, а в `pm2 logs seeds`
появится строка `[mail] адрес уведомлений … не похож на почту`.

После правки:

```bash
cd /var/www/seeds/seeds
node scripts/check-mail.mjs твоя@почта.ru   # покажет итоговый список получателей
bash deploy/update.sh                       # перечитать .env.production
``` Отправка идёт с основного ящика
(`SMTP_USER`), но с разным именем отправителя — «Заказы · Томат Семена»,
«Отзывы · …», «Поддержка · …» — во входящих письма сразу различимы, легко
настроить фильтры по папкам.

### Отдельные ящики-отправители order@ / review@ / support@ (по желанию)

Если завёл в панели рег.ру полноценные ящики `order@`, `review@`, `support@`
(у каждого свой пароль — задаётся при создании ящика, сменить можно через
«…» → «Изменить» в списке ящиков), пропиши каждому логин и пароль:

```
# Заказы — письма «Новый заказ» уходят с этого ящика
SMTP_USER_ORDERS=order@tomatsemena.ru
SMTP_PASSWORD_ORDERS=пароль ящика order@

# Отзывы — письма «Новый отзыв»
SMTP_USER_REVIEWS=review@tomatsemena.ru
SMTP_PASSWORD_REVIEWS=пароль ящика review@

# Поддержка — письма «Вопрос в поддержке»
SMTP_USER_SUPPORT=support@tomatsemena.ru
SMTP_PASSWORD_SUPPORT=пароль ящика support@
```

Хост и порт у всех общие — те же `SMTP_HOST`/`SMTP_PORT` (у рег.ру
`mail.hosting.reg.ru:465`). Имя отправителя подставится само («Заказы · Томат
Семена <order@…>»); если хочешь другое — переопредели через
`MAIL_FROM_ORDERS="Своё имя <order@tomatsemena.ru>"` (аналогично REVIEWS и
SUPPORT). Категории без пары SMTP_USER_*/SMTP_PASSWORD_* шлются с основного
ящика — можно настроить только часть.

### Проверка

```bash
cd /var/www/seeds/seeds
node scripts/check-mail.mjs твоя@почта.ru   # проверит основной ящик И все настроенные order@/review@/support@
bash deploy/update.sh
```

Потом вживую: оформи тестовый заказ, оставь отзыв, отправь вопрос через
`/support` — на `service@` упадут три письма от трёх отправителей. Если
чего-то нет — `pm2 logs seeds`, строки `[mail]` (чаще всего — неверный пароль
ящика или адрес в MAIL_FROM_* не совпадает с ящиком отправки).

## Письма на Mail.ru приходят с задержкой

Симптом: код восстановления пароля на `@yandex.ru` приходит мгновенно, а на
`@mail.ru`/`@bk.ru`/`@list.ru` — через 5–20 минут. Это **не тормоза сайта**:
письмо сдаётся на SMTP за доли секунды, дальше его придерживает принимающая
сторона.

Сначала подтвердите это по логам — сайт печатает время сдачи каждого письма:

```bash
pm2 logs seeds --lines 200 | grep "\[mail\]"
# [mail] «Код подтверждения: 123456 — Томат Семена» → ...@mail.ru за 480 мс
```

Сотни миллисекунд здесь и письмо, дошедшее через 10 минут, — задержка на
стороне Mail.ru. Почему так бывает:

1. **Серые списки (greylisting).** Mail.ru отклоняет первое письмо от
   незнакомого отправителя временной ошибкой, и отправляющий сервер повторяет
   попытку через несколько минут. Лечится «прогревом» — после нескольких
   доставленных писем адрес запоминается — и пунктами 2–3.
2. **Нет SPF / DKIM / DMARC у домена отправителя.** Главная причина. Проверить:

   ```bash
   node scripts/check-mail.mjs твоя@почта.ru   # печатает найденные SPF/DKIM/DMARC
   ```

   Чего не хватает — добавьте TXT-записями в DNS домена (значения выдаёт панель
   почтового провайдера). DMARC можно начать с мягкого
   `v=DMARC1; p=none; rua=mailto:postmaster@tomatsemena.ru`.
3. **`MAIL_FROM` из другого домена, чем `SMTP_USER`.** Сайт подставляет в
   конверт письма адрес `SMTP_USER` (Return-Path), чтобы сходилась проверка
   SPF, но заголовок «От кого» остаётся вашим — расхождение доменов фильтры
   всё равно считают подозрительным. Держите оба ключа на одном ящике.
4. **Репутация IP.** Загляните в [postmaster.mail.ru](https://postmaster.mail.ru) —
   добавьте домен, там видно долю спам-жалоб и ошибки доставки. Отправка идёт с
   IP почтового провайдера (Яндекс, рег.ру), поэтому свой VPS в белые списки
   добавлять не нужно.

Пока задержки не вылечены, покупателю помогает запас по времени на стороне
сайта:

- код действует **5 минут**; поменять — `EMAIL_CODE_TTL_MIN` в
  `.env.production` (целое число минут, от 1 до 60):

  ```
  EMAIL_CODE_TTL_MIN=15
  ```

- при повторной отправке **прежние коды продолжают работать**, пока не вышел
  их собственный срок: если оба письма придут с разницей в минуты, подойдёт
  любое из них;
- на экране ввода идёт обратный отсчёт, а по нулю сразу предлагается запросить
  новый код.

## Если что-то не так

| Симптом | Что делать |
|---------|-----------|
| `check-mail` пишет «логин/пароль не подходят» | Нужен **пароль приложения**, не пароль от почты; в Яндексе включить доступ по IMAP/SMTP |
| Письма уходят, но попадают в спам | Добавь SPF и DKIM записи в DNS (шаг 1.2), подожди пару часов |
| Код на Mail.ru идёт 10 минут | Раздел «Письма на Mail.ru приходят с задержкой» выше |
| «сервер недоступен» / таймаут | Проверь SMTP_HOST/PORT; исходящий порт 25 у VPS часто закрыт — используй 465 |
| После первой оплаты не пришёл пароль от кабинета | Проверьте SMTP через `node scripts/check-mail.mjs`, адрес покупателя и строки `[account]`/`[mail]` в `pm2 logs seeds` |
| Письма о заказе не приходят гостю | Проверьте адрес из заказа и точные ошибки в `pm2 logs seeds` (строки `[mail]`) |
