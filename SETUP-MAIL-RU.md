# ✉️ Почта магазина: код при регистрации + письма о статусе заказа

Что уже сделано в коде (включается ключами SMTP, без них всё работает как раньше):

- **Регистрация с подтверждением почты**: на `/register` после формы приходит
  письмо с 6-значным кодом; аккаунт создаётся только после ввода кода
  (почта в аккаунте гарантированно настоящая).
- **Письма о заказе** — приходят и гостям, и зарегистрированным (почта берётся
  из формы оформления заказа, аккаунт не нужен):
  - «Заказ принят» — сразу после оформления, с составом и суммой;
  - «Оплата получена» — после онлайн-оплаты (по callback Альфы);
  - «В обработке» / «Отправлен» (с трек-номером) / «Выполнен» / «Отменён» —
    при смене статуса в админке;
  - «Возврат оформлен» — при возврате денег.

Это решает вопрос «гость оплатил и пропал»: покупатель без аккаунта получает
номер заказа и все изменения статуса на почту.

---

## Шаг 1. Почтовый ящик, с которого шлём

Лучше всего — ящик на своём домене: `info@tomatsemena.ru`. Бесплатный способ —
**Яндекс 360 для бизнеса** (бесплатный тариф):

1. [admin.yandex.ru](https://admin.yandex.ru) → добавить организацию → подключить
   домен `tomatsemena.ru` (подтверждение — TXT-запись в DNS).
2. Добавить DNS-записи, которые покажет Яндекс: **MX**, **SPF** (TXT) и
   **DKIM** — без SPF/DKIM письма улетают в спам, это обязательная часть.
3. Создать ящик `info@tomatsemena.ru`.
4. В настройках ящика: включить «Доступ по IMAP/SMTP» и создать
   **пароль приложения** (Безопасность → Пароли приложений) — именно он пойдёт
   в `SMTP_PASSWORD`, обычный пароль от почты работать не будет.

Альтернативы с теми же шагами: VK WorkMail (biz.mail.ru), почта хостера.
Можно временно слать и с обычного ящика (`что-то@yandex.ru`) — тоже через
пароль приложения, но письма «от домена» выглядят солиднее.

## Шаг 2. Ключи на сервере

В `.env.production` добавь:

```
SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
SMTP_USER=info@tomatsemena.ru
SMTP_PASSWORD=пароль-приложения
MAIL_FROM="Томат Семена <info@tomatsemena.ru>"
```

> `MAIL_FROM` должен совпадать с ящиком `SMTP_USER` (или его алиасом) — иначе
> провайдер отклонит отправку.

## Шаг 3. Проверить и включить

```bash
cd /var/www/seeds/seeds
node scripts/check-mail.mjs твоя@почта.ru   # тестовое письмо + подсказки при ошибке
bash deploy/update.sh                        # пересборка и перезапуск сайта
```

Проверка вживую:
- `/register` — после формы должен появиться экран «Подтвердите почту», код
  приходит письмом;
- оформи тестовый заказ со своей почтой — придёт «Заказ принят»; смени статус
  в `/admin/orders` — придёт письмо о статусе.

## Если что-то не так

| Симптом | Что делать |
|---------|-----------|
| `check-mail` пишет «логин/пароль не подходят» | Нужен **пароль приложения**, не пароль от почты; в Яндексе включить доступ по IMAP/SMTP |
| Письма уходят, но попадают в спам | Добавь SPF и DKIM записи в DNS (шаг 1.2), подожди пару часов |
| «сервер недоступен» / таймаут | Проверь SMTP_HOST/PORT; исходящий порт 25 у VPS часто закрыт — используй 465 |
| На /register нет экрана с кодом | SMTP-ключи не заданы или сайт не пересобран — `node scripts/check-mail.mjs` и `bash deploy/update.sh` |
| Письма о заказе не приходят гостю | Покупатель не указал почту в форме заказа (поле необязательное) — это ок; точные ошибки отправки видны в `pm2 logs seeds` (строки `[mail]`) |
