# 💳 Приём оплаты через Robokassa (пошагово)

Код интеграции уже написан и работает «в спящем режиме»: пока ключи Robokassa не
заданы — сайт работает как сейчас (заказ без онлайн-оплаты). Как только добавишь
ключи и пересоберёшь — на оформлении заказа появится переход на платёжную
страницу Robokassa (карты, СБП, кошельки, рассрочка), а оплаченные заказы будут
помечаться в админке.

Что уже сделано в коде:
- подпись и переход на оплату при оформлении заказа (`app/api/checkout`);
- **заказ появляется в базе только после оплаты**: до неё всё лежит в черновике
  (`payment_drafts`, в админке его нет), поэтому брошенные попытки не оставляют
  «пустышек» в заказах и не съедают номера (`lib/order-draft.ts`);
- приём уведомления об оплате с проверкой подписи — Result URL
  (`app/api/payment/callback`);
- возврат покупателя с оплаты — Success/Fail URL (`app/payment/success`,
  `app/payment/fail`), тоже с проверкой подписи;
- сверка состояния платежа напрямую у Robokassa (XML-интерфейс `OpStateExt`) —
  при подтверждении оплаты, уборке зависших заказов и отметке возврата;
- фискальный чек (54-ФЗ) с номенклатурой, скидкой и доставкой — по флагу;
- уборка протухших черновиков со сверкой у Robokassa: если деньги всё-таки
  получены, а уведомление не дошло, заказ достраивается сам
  (`lib/order-cleanup.ts`);
- возврат оплаты из админки — через Refund API на Пароле #3, а без него —
  отметка возврата, сделанного в личном кабинете (`/admin/orders`);
- страницы для модерации: `/offer` (оферта), `/returns` (возврат),
  `/requisites` (реквизиты), плюс уже были `/privacy`, `/delivery`.

Дальше — то, что можешь сделать только ты (регистрация, касса, юр-данные).

---

## Шаг 0. Заполнить реквизиты ИП (нужно для модерации магазина)

Открой и впиши **свои реальные данные ИП** вместо `[в скобках]`:
- `app/requisites/page.tsx` — наименование ИП, ИНН, ОГРНИП, адрес, телефон;
- `app/privacy/page.tsx` — там же наименование/ИНН/адрес оператора;
- проверь `app/offer/page.tsx` и `app/returns/page.tsx` под свой магазин.

Правь локально или прямо в GitHub, потом на сервере `bash deploy/update.sh`.

## Шаг 1. Зарегистрировать магазин в Robokassa

1. Регистрация на robokassa.ru → личный кабинет **partner.robokassa.ru**.
2. «Мои магазины» → добавить магазин: сайт `https://tomatsemena.ru`, вид
   деятельности, описание товара (семена), контакты.
3. Заполнить данные ИП и загрузить документы — Robokassa проверяет сайт
   (нужны рабочие страницы из шага 0 + HTTPS: уже есть).
4. После проверки магазин активируют, и станут доступны боевые пароли.

**Идентификатор магазина** (он же MerchantLogin) виден в ЛК — это НЕ e-mail и не
логин от кабинета, а короткое имя магазина, например `tomatsemena`.

## Шаг 2. Технические настройки магазина

ЛК Robokassa → «Мои магазины» → магазин → **Технические настройки**. Заполни:

| Поле | Значение |
|------|----------|
| Result URL | `https://tomatsemena.ru/api/payment/callback` |
| Метод отсылки данных по Result URL | **POST** |
| Success URL | `https://tomatsemena.ru/payment/success` |
| Метод отсылки данных по Success URL | POST или GET (сайт понимает оба) |
| Fail URL | `https://tomatsemena.ru/payment/fail` |
| Метод отсылки данных по Fail URL | POST или GET |
| Алгоритм расчёта хеша | **MD5** (или другой — тогда впиши его в `ROBOKASSA_HASH`) |

Там же задаются пароли магазина:

| Пароль | Для чего |
|--------|----------|
| **Пароль #1** | им сайт подписывает счёт при переходе на оплату |
| **Пароль #2** | им Robokassa подписывает уведомление об оплате (Result URL) |
| **Пароль #3** | ключ Refund API — с ним сайт возвращает деньги прямо из админки |

Плюс отдельная пара **тестовых** Пароль #1 и Пароль #2 для песочницы.

Пароль #3 не обязателен: без него оплата работает полностью, а возврат делается
в личном кабинете и отмечается в админке (см. раздел «Возвраты»).

> Result URL — главный канал: именно по нему заказ становится «оплачен».
> Success URL — это просто возврат покупателя в браузере, ему сайт верит только
> при верной подписи.

## Шаг 3. Онлайн-касса (54-ФЗ)

При онлайн-оплате нужно пробивать чек и отправлять его покупателю и в ФНС.
У Robokassa это встроено: в ЛК подключается **фискализация** (собственная касса
Robokassa или своя ККТ) — тогда чек формируется автоматически.

Два варианта, как сайт передаёт состав чека:

- **Просто и без настроек**: `ROBOKASSA_RECEIPT` не задан. Robokassa пробьёт чек
  одной строкой по описанию платежа («Заказ №123») на всю сумму.
- **Правильно по номенклатуре** (рекомендуется): `ROBOKASSA_RECEIPT=on`. Сайт
  сам собирает чек: каждый товар отдельной позицией, доставка — позицией-услугой,
  скидка по промокоду разносится по товарам так, что сумма чека копейка в
  копейку совпадает с суммой платежа. Обязательно укажи систему налогообложения
  `ROBOKASSA_SNO` (например `usn_income`) и ставку НДС `ROBOKASSA_TAX`
  (для УСН без НДС — `none`).

> Нужны: договор с ОФД из списка ФНС, регистрация ККТ в ФНС (нужна КЭП),
> фискальный накопитель (для ИП на УСН — ФН на 36 месяцев). Если арендуешь кассу
> у Robokassa — всё это делается через них.

## Шаг 4. Сначала тест (песочница)

Тестовый режим — это те же боевые адреса, но с параметром `IsTest=1` и
**тестовыми паролями** из технастроек. Реальные деньги не списываются.

На сервере в `.env.production` добавь:

```
SITE_URL=https://tomatsemena.ru
ROBOKASSA_LOGIN=идентификатор-магазина
ROBOKASSA_TEST=1
ROBOKASSA_TEST_PASSWORD1=тестовый-пароль-1
ROBOKASSA_TEST_PASSWORD2=тестовый-пароль-2
# Боевые пароли можно вписать сразу — в тестовом режиме они не используются:
ROBOKASSA_PASSWORD1=боевой-пароль-1
ROBOKASSA_PASSWORD2=боевой-пароль-2
ROBOKASSA_PASSWORD3=боевой-пароль-3
```

Пересобери: `bash deploy/update.sh` (ключи вшиваются при сборке — просто
перезапуска мало).

Проверь связь и подписи, не оформляя заказ:

```bash
npm run check:pay      # или: node scripts/check-robokassa.mjs
```

Скрипт проверит логин + Пароль#2 через XML-интерфейс и напечатает ссылку на
пробный платёж на 1 ₽ — по ней видно, принимается ли Пароль#1.

Дальше оформи тестовый заказ на сайте: должно перебросить на платёжную страницу
Robokassa. Оплати тестовым способом → вернёшься на страницу заказа, а в
`/admin/orders` заказ получит статус **«Оплачен»**.

> Тестовые оплаты не видны в разделе «Операции» ЛК — так и должно быть.

## Шаг 5. Боевой режим

Когда тесты прошли и магазин активирован — убери тестовый режим:

```
ROBOKASSA_TEST=0
ROBOKASSA_PASSWORD1=боевой-пароль-1
ROBOKASSA_PASSWORD2=боевой-пароль-2
ROBOKASSA_PASSWORD3=боевой-пароль-3
```

`bash deploy/update.sh`, потом **контрольный платёж реальной картой** на
маленькую сумму → проверь, что заказ стал «Оплачен» и деньги видны в ЛК.

## Готово

- Оформление → оплата на странице Robokassa → заказ «Оплачен» в `/admin`.
- Чек по 54-ФЗ формирует Robokassa (если подключена фискализация).
- Возврат — см. следующий раздел.

## Возвраты

**Если задан `ROBOKASSA_PASSWORD3`** (Пароль #3 из технастроек) — возврат
делается прямо в админке: заказ → **«Вернуть оплату»** → весь заказ или
отдельные товары → «Вернуть». Сайт сам находит операцию по номеру счёта, шлёт
запрос в Refund API, помечает возвращённые позиции и отправляет покупателю
письмо. Возврат у Robokassa асинхронный: отказ виден сразу, а «исполнено» может
прийти через несколько минут — тогда админка предупредит, что подтверждения ещё
нет. Деньги возвращаются на карту покупателя за 1–10 дней.

**Если Пароля #3 нет** — возврат делается в личном кабинете:
partner.robokassa.ru → «Операции и возвраты» → найди операцию по номеру счёта →
«Вернуть» (полностью или частично). После этого в админке сайта: заказ →
**«Отметить возврат»** → «Отметить». Второй шаг нужен, чтобы сошлись статус
заказа, остаток к возврату и письмо покупателю; сайт заодно сверяется с
Robokassa и предупредит, если возврата там ещё не видно.

Номер счёта показан в модальном окне возврата — по нему операция и ищется в ЛК.

## Переменные окружения

| Переменная | Зачем |
|------------|-------|
| `ROBOKASSA_LOGIN` | идентификатор магазина (MerchantLogin) |
| `ROBOKASSA_PASSWORD1` | Пароль #1 — подпись исходящего счёта |
| `ROBOKASSA_PASSWORD2` | Пароль #2 — проверка уведомления об оплате |
| `ROBOKASSA_PASSWORD3` | Пароль #3 — ключ Refund API (возврат прямо из админки). Не обязателен |
| `ROBOKASSA_TEST` | `1` — тестовый режим (`IsTest=1`) |
| `ROBOKASSA_TEST_PASSWORD1/2` | тестовые пароли (используются при `ROBOKASSA_TEST=1`) |
| `ROBOKASSA_HASH` | алгоритм хеша из технастроек: `md5` (по умолчанию), `sha1`, `sha256`, `sha384`, `sha512`, `ripemd160` |
| `ROBOKASSA_RECEIPT` | `on` — слать фискальный чек с номенклатурой |
| `ROBOKASSA_SNO` | система налогообложения в чеке: `usn_income`, `usn_income_outcome`, `osn`, `patent`, `envd`, `esn` |
| `ROBOKASSA_TAX` | ставка НДС в чеке: `none` (по умолчанию), `vat0`, `vat10`, `vat20`… |
| `ROBOKASSA_RECEIPT_ENCODE` | как чек попадает в подпись: `url` (по умолчанию), `raw` или `both` |
| `ROBOKASSA_INVOICE_TTL_MIN` | срок жизни счёта в минутах (по умолчанию 20; `0` — не ограничивать) |
| `SITE_URL` | публичный адрес сайта (адреса возврата с оплаты) |

Оплата включается, только когда заданы `ROBOKASSA_LOGIN`, `ROBOKASSA_PASSWORD1`
и `ROBOKASSA_PASSWORD2`: без Пароля #2 сайт не смог бы отличить настоящее
уведомление об оплате от поддельного, поэтому такую «оплату» он не включает.

## Как это работает внутри (коротко)

1. Покупатель оформляет заказ → сайт резервирует товар и промокод и складывает
   всё для будущего заказа в **черновик оплаты** (`payment_drafts`). Заказа в
   базе ещё нет. Черновику присваивается номер счёта `InvId`, и параметры
   платежа подписываются Паролем #1
   (`MerchantLogin:OutSum:InvId[:Receipt]:Пароль#1`).
2. Браузер отправляет **POST-форму** на `auth.robokassa.ru/Merchant/Index.aspx`
   (POST, а не ссылка: чек с номенклатурой не влезает в длину URL, и параметры
   не остаются в истории браузера).
3. После оплаты Robokassa вызывает **Result URL**. Сайт проверяет подпись
   Паролем #2, сверяет сумму с суммой черновика, дополнительно спрашивает
   состояние операции у Robokassa — и только тогда **создаёт заказ** (сразу со
   статусом «оплачен»), шлёт письма покупателю и продавцу и отвечает
   `OK<номер счёта>`.
4. Покупателя возвращают на **Success URL**; там подпись проверяется Паролем #1.
   Если уведомление ещё не дошло, сайт сам переспрашивает Robokassa и создаёт
   заказ, чтобы покупатель сразу увидел номер. Корзина чистится и цель «покупка»
   в Метрике засчитывается только при верной подписи.
5. Если оплаты не было — заказа в базе так и не появится. Через 20 минут уборка
   (`/api/cron/cleanup`) удалит черновик, вернув товар на склад и промокод
   покупателю. Счёт в Robokassa к этому моменту уже протух (`ExpirationDate`),
   поэтому оплатить отменённый черновик нельзя. Если же деньги всё-таки
   получены, а уведомление не дошло, уборка не удаляет черновик, а достраивает
   по нему заказ.

## Полезное / на что смотреть

- **СБП дешевле карт.** На странице Robokassa способы оплаты включаются в ЛК —
  отдельный код для этого не нужен.
- **Комиссия** зависит от способа оплаты и оборота — смотри тариф в ЛК.
- **НДС и порог УСН на 2026** — уточни у бухгалтера и правильно укажи систему
  налогообложения (`ROBOKASSA_SNO`).
- Диагностика: `npm run check:pay` (ключи и связь с Robokassa прямо с сервера),
  `/api/health` (база), `pm2 logs seeds` — туда пишутся точные ошибки оплаты
  (строки `[robokassa]`).
- Сертификаты Минцифры для Robokassa **не нужны** — сервис работает на обычном
  публичном TLS.

## Если что-то не так

Первым делом: `npm run check:pay` на сервере — он сам назовёт причину.
Точные ошибки также видны в `pm2 logs seeds` (строки `[robokassa]`).

| Симптом | Что делать |
|---------|-----------|
| На оформлении нет перехода на оплату | Не заданы `ROBOKASSA_LOGIN`/`PASSWORD1`/`PASSWORD2` или не пересобрал — проверь `.env.production` и `bash deploy/update.sh` |
| Robokassa пишет «неверная подпись» / ошибка в параметрах | Пароль #1 не тот (боевой вместо тестового или наоборот) либо `ROBOKASSA_HASH` не совпадает с алгоритмом в технастройках |
| Ошибка 29 при тестовой оплате | Включён `ROBOKASSA_TEST=1`, но пароли не тестовые — впиши `ROBOKASSA_TEST_PASSWORD1/2` |
| Оплата прошла, а заказа в админке нет | Не заполнен Result URL в технастройках, выбран не тот метод, или Пароль #2 не совпадает (в ЛК видно, доставлено ли уведомление). Заказ всё равно достроится ближайшей уборкой — она сверяется с Robokassa |
| В логах «сумма уведомления не совпадает» | Заказ меняли после выставления счёта — оплату сайт намеренно не засчитывает; разбирайся вручную |
| В логах «черновик заказа не найден» | Черновик успели убрать, а оплата всё-таки прошла — верни деньги в ЛК или заведи заказ вручную |
| Чек не приходит покупателю | Фискализация не подключена в ЛК Robokassa, либо при `ROBOKASSA_RECEIPT=on` не задан `ROBOKASSA_SNO` |
| Ошибка подписи только при включённом чеке | Попробуй `ROBOKASSA_RECEIPT_ENCODE=raw` (у части магазинов чек участвует в подписи «сырым» JSON) |
| Возврат не проходит | Возврат возможен только для заказа в статусе «Оплачен» и только на остаток. «Robokassa не нашла операцию» — у заказа нет номера счёта (оформлен до перехода на Robokassa) |
| Схема базы устарела | После обновления запусти `npm run db:schema` — появятся коллекция `payment_drafts` и поле `invoice_id` у заказов |
