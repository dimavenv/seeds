# Перенос товаров с Ozon на сайт

Скрипт `scripts/import-ozon.mjs` автоматически переносит товары из вашего магазина
на Ozon в базу сайта (Supabase): **названия, цены, описания и все фотографии**.
Фото скачиваются и сохраняются в наше хранилище (Supabase Storage), а не
подгружаются с Ozon.

## Что нужно заранее

1. **Применить миграции** в Supabase → SQL Editor, включая
   `supabase/migrations/0004_product_images.sql` (колонка `images` для нескольких
   фото) и `0002_storage.sql` (bucket `product-images`).
2. **Ключи Ozon Seller API.** В личном кабинете продавца Ozon:
   **Настройки → Seller API → Сгенерировать ключ** (роль «Администратор»).
   Скопируйте **Client-Id** и **Api-Key**.
3. Локально установленный проект (`npm install`) и файл `.env.local`.

## Настройка `.env.local`

Добавьте к уже имеющимся ключам Supabase:

```
NEXT_PUBLIC_SUPABASE_URL=...          # уже есть
SUPABASE_SERVICE_ROLE_KEY=...         # уже есть (нужен для записи в обход RLS)

OZON_CLIENT_ID=ваш-client-id
OZON_API_KEY=ваш-api-key
```

## Запуск

Сначала **пробный прогон** (ничего не пишет, только показывает, что нашлось):

```bash
npm run import:ozon -- --dry --limit=20
```

Если список выглядит правильно — **реальный импорт**:

```bash
npm run import:ozon
```

Скрипт идемпотентный: товары привязываются к стабильному `slug` вида
`ozon-<артикул>`, поэтому повторный запуск **обновляет** товары, а не плодит
дубли.

## Полезные опции

| Опция | Что делает |
|-------|------------|
| `--dry` | тест без записи в базу |
| `--limit=20` | импортировать только первые 20 (для пробы) |
| `--images=8` | максимум фото на товар (по умолчанию 6) |
| `--no-desc` | без описаний (быстрее) |
| `--skip-existing` | пропускать уже импортированные (продолжить прерванный импорт) |
| `--stock=100` | какой остаток ставить новым товарам (по умолчанию 100) |
| `--link-images` | НЕ перезаливать фото к нам, а сохранить прямые ссылки Ozon CDN |
| `--only-desc` | дописать ТОЛЬКО описания к уже импортированным товарам |
| `--chunk=25` | размер пачки записи (меньше = надёжнее на слабой сети) |

Пример: `npm run import:ozon -- --images=5 --skip-existing`

### Добавить описания позже (если импортировали с `--no-desc`)

Описания можно дописать отдельным быстрым прогоном — он не трогает фото, цены и
категории, а только обновляет колонку «описание» (тело запроса крошечное, поэтому
проходит даже на нестабильной сети):

```bash
npm run import:ozon -- --only-desc
```

### Если загрузка фото в Storage зависает («таймаут»/«aborted»)

На некоторых сетях (провайдер/VPN/роутер) исходящие «тяжёлые» POST-запросы с
картинками в Supabase Storage зависают, хотя сам сайт и чтение базы работают.
В этом случае запустите импорт со ссылками на фото Ozon — без перезаливки:

```bash
npm run import:ozon -- --link-images
```

Тогда фото будут показываться напрямую с CDN Ozon (домены уже разрешены в
`next.config.mjs`). Это быстро и работает на любой сети. Минус: если Ozon когда-то
удалит/сменит картинку — она пропадёт. Позже, с другой сети, можно перезалить их к
себе обычным `npm run import:ozon` (он обновит те же товары).

## Категории

Категория определяется **автоматически по названию** товара (есть «томат» →
Томаты, «перец сладкий» → Перец сладкий, «чили/острый» → Перец чили, и т.д.).
Что не распозналось — попадёт **без категории**; такие товары можно открыть в
`/admin/products` и проставить категорию вручную.

## После импорта

- Проверьте товары в каталоге и в `/admin/products`.
- Остаток у всех ставится одинаковый (по умолчанию 100) — скорректируйте при
  необходимости в админке.
- Отметки «Новинка/Хит» не выставляются — отметьте нужные товары в админке.

## Если что-то пошло не так

- **401/403 от Ozon** — неверные `OZON_CLIENT_ID`/`OZON_API_KEY` или у ключа нет
  прав. Перевыпустите ключ с ролью «Администратор».
- **Ошибка загрузки фото / upload** — проверьте, что bucket `product-images`
  существует и публичный (`0002_storage.sql`).
- **Долго / лимиты (429)** — Ozon ограничивает частоту запросов; скрипт сам ждёт
  и повторяет. Для 500 товаров с фото импорт может занять 10–30 минут.
